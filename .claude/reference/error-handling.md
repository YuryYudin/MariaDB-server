# Reference: Error / warning / logging handling

## 1. TL;DR

- **Three audiences, three APIs.** The **SQL client** (errors abort the
  statement, warnings continue and appear in `SHOW WARNINGS`), the
  **error log** (operators / DBAs reading log files via `sql_print_*`),
  and the **DBUG trace** (developer inspection via `DBUG_PRINT`).
  Picking the wrong API is the most common bug shape here.
- **New error codes go at the END of [`sql/share/errmsg-utf8.txt`](../../sql/share/errmsg-utf8.txt).**
  Numeric codes are a stable ABI — never insert, never reorder. The
  header `include/mysqld_error.h` is regenerated by `comp_err` at build
  time; do not hand-edit.
- **MariaDB does not throw C++ exceptions.** `my_error()` *sets* state
  on the `THD`; the caller propagates by returning non-zero. A
  `my_error()` followed by `return 0` silently swallows the error (§6).
- Wording / format-specifier / identifier-quoting rules are
  authoritative in
  [`.claude/review/logging-and-errors.md`](../review/logging-and-errors.md);
  the procedural "how to add a new code" is in
  [`.claude/playbooks/add-error-message.md`](../playbooks/add-error-message.md).
  This doc is the conceptual side.

## 2. The decision table — which API to use

Extended from [`sql/CLAUDE.md`](../../sql/CLAUDE.md) §"`my_error()` vs
`push_warning_printf()` vs `sql_print_error()`":

| If the message is… | Use | Visible to | Notes |
|---|---|---|---|
| Statement-aborting error | `my_error(ER_*, MYF(0), …)` | SQL client | Sets `DA_ERROR` on `Diagnostics_area`; `thd->is_error()` becomes true. Caller must propagate via non-zero return. |
| Continuing warning | `push_warning_printf(thd, Sql_condition::WARN_LEVEL_WARN, ER_*, ER_THD(thd, ER_*), …)` | SQL client (in `SHOW WARNINGS`) | Adds an `Sql_condition` to `Warning_info`; statement keeps running. |
| Continuing note (lower severity) | `push_warning_printf(…, WARN_LEVEL_NOTE, …)` | SQL client (in `SHOW WARNINGS`) | Often hidden by the client's `sql_notes` setting; for informative-but-noisy diagnostics. |
| Server-side info | `sql_print_information(fmt, …)` | Error log | Plain `printf`-style format. **No** `errmsg-utf8.txt` entry needed. Not in `SHOW WARNINGS`. |
| Server-side warning | `sql_print_warning(fmt, …)` | Error log | Same. |
| Server-side error | `sql_print_error(fmt, …)` | Error log | Same. Does **not** abort the statement and does **not** set `thd->is_error()`. |
| DBA / developer diagnostic | `DBUG_PRINT("tag", ("fmt", …))` | DBUG trace (`mariadbd --debug=…`) | Debug build only; compiled out in non-`Debug` builds. |
| User-defined condition (SQL) | `SIGNAL SQLSTATE '45000' …` | SQL client | See §8. Creates an `Sql_condition` directly, bypassing numeric `ER_*`. |

Forbidden in server code
([`logging-and-errors.md`](../review/logging-and-errors.md) §"Logging
functions"): `printf`, `fprintf(stderr, …)`, `puts`, `ib::logger` in
*new* InnoDB code, `fprintf("%s", …)` (use `fwrite()`).

## 3. `Sql_condition` — one warning / error

[`sql/sql_error.h:355`](../../sql/sql_error.h). Each condition holds:

- **Level** — `WARN_LEVEL_NOTE`, `WARN_LEVEL_WARN`, or `WARN_LEVEL_ERROR`
  (`enum_warning_level` at `sql_error.h:163`). Severity *classification*
  — does **not** itself determine whether the statement aborts (§11).
- **Numeric code** — the `ER_*` value (`uint sql_errno`).
- **SQLSTATE** — 5-char per SQL:2003 (`HY000`, `42S22`, …).
- **Message text** — formatted, locale-resolved.
- **Optional** table / column / cursor / class / subclass etc.

Constructors are `private`; only `THD`, `Warning_info`, `Sql_cmd_signal`,
`Sql_cmd_resignal`, and `sp_rcontext` are friended (`sql_error.h:396-402`).
All ordinary code goes through `my_error()` / `push_warning*()`.

## 4. `Diagnostics_area` vs `Warning_info`

Two distinct collections per statement — both reachable from
`THD::get_stmt_da()`:

- **`Diagnostics_area`** ([`sql_error.h:989`](../../sql/sql_error.h))
  holds the statement's overall **outcome**: one of `DA_EMPTY` / `DA_OK`
  / `DA_EOF` / `DA_ERROR` / `DA_DISABLED` etc. Set once per statement
  (cannot be reassigned). After `my_error()`, status is `DA_ERROR` and
  `thd->is_error()` returns true. Holds **the** error (sql_errno,
  message, sqlstate).
- **`Warning_info`** ([`sql_error.h:516`](../../sql/sql_error.h)) holds
  the accumulated **list** of `Sql_condition`s — notes, warnings, *and*
  errors. `SHOW WARNINGS` reads this list. Counters per level live in
  `m_warn_count[WARN_LEVEL_*]`.

An error sets both (`DA_ERROR` *and* a condition on `Warning_info`),
but their lifetimes differ: `Warning_info` can span multiple statements
(the `HANDLER` simulation), `Diagnostics_area` resets per statement.

## 5. `THD::is_error()` vs `THD::is_fatal_error`

Two distinct booleans, frequently confused:

- **`thd->is_error()`** ([`sql_class.h:5033`](../../sql/sql_class.h))
  delegates to `m_stmt_da->is_error()` (status == `DA_ERROR`). Set by
  `my_error()`. Means "there is a pending error to surface to the
  client". Reset between statements *and* between sub-statements in
  stored programs (§11).
- **`thd->is_fatal_error`** (`sql_class.h:4272`) — bare `bool`, "this
  compound statement cannot continue at all". Set by
  `THD::fatal_error()` (`sql_class.h:5014`), which asserts an error is
  already on the DA. Used for OOM / unrecoverable decode. Disables
  stored-routine `CONTINUE` / `EXIT` handlers — a `DECLARE CONTINUE
  HANDLER FOR …` cannot mask a fatal error.
- **`thd->is_fatal_sub_stmt_error`** (`sql_class.h:4290`) — sibling
  flag for sub-statement (trigger / SQL function) mode.

Common shapes: `if (thd->is_error()) return 1;` to bail; `if
(thd->is_fatal_error) /* don't try to recover */`; `my_error(…); thd->fatal_error();`
to mark unrecoverable (or `my_error(ER_FOO, MYF(ME_FATAL), …)` — see §7).

## 6. Error throwing vs error setting

MariaDB Server does **not** use C++ exceptions. `my_error()` *sets*
state; callers propagate via return values.

```c
if (!(buf= (char*) alloc_root(mem_root, n)))
{
  my_error(ER_OUTOFMEMORY, MYF(0), n);  // SETS the error
  return TRUE;                          // PROPAGATES it
}
```

The function returns a status code (typically `bool`/`int`; in `sql/`,
`TRUE`/non-zero = error, `0` = OK). The two-step is the whole convention.

**Common bug shape A** — silently swallowed error:

```c
my_error(ER_FOO, MYF(0), name);   // error on DA …
return 0;                         // … caller sees "success"
```

The DA holds a pending error, the next statement overwrites it, the
user sees nothing. Defence: `DBUG_ASSERT(thd->is_error())` at error
return sites; `DBUG_ASSERT(!thd->is_error())` on success returns.

**Common bug shape B** — meaningless generic failure:

```c
if (do_thing(thd))   // returned non-zero …
  return 1;          // … but did anyone call my_error()?
```

If `do_thing()` returns non-zero without setting an error, callers
report `ER_UNKNOWN_ERROR` (or similar) and the user has no clue.

## 7. OOM (out of memory)

Canonical pattern after `alloc_root` / `my_malloc` returns `NULL`:

```c
ptr= (T*) alloc_root(mem_root, n);
if (!ptr)
{
  my_error(ER_OUTOFMEMORY, MYF(0), n);
  return TRUE;
}
```

For unrecoverable cases use `MYF(ME_FATAL)`:

```c
my_error(ER_OUTOFMEMORY, MYF(ME_FATAL), bytes);
```

`MYF()` flag bits ([`include/my_sys.h`](../../include/my_sys.h) lines
107-111): `ME_ERROR_LOG` (64) — also write to error log;
`ME_ERROR_LOG_ONLY` (128); `ME_NOTE` (1024); `ME_WARNING` (2048);
`ME_FATAL` (4096). See
[`.claude/reference/memory-management.md`](memory-management.md) for
`MEM_ROOT` lifetimes.

## 8. SIGNAL / RESIGNAL — user-defined conditions

[`sql/sql_signal.cc`](../../sql/sql_signal.cc) implements the SQL
`SIGNAL` / `RESIGNAL` statements. These create `Sql_condition`s
**directly** via `THD::raise_condition()`
(`Sql_cmd_common_signal::raise_condition`, `sql_signal.cc:356`), with
full control over class / subclass / SQLSTATE / message — including
SQLSTATEs **not** mapped to any `ER_*` code:

```sql
SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'application error';
```

`RESIGNAL` (`sql_signal.cc:425`) re-raises the active condition inside
a stored-routine handler; requires an active handler
(`ER_RESIGNAL_WITHOUT_ACTIVE_HANDLER` otherwise).

Implication: C++ code processing the DA after stored-routine execution
may see `sql_errno()` values not in `errmsg-utf8.txt`. Don't assume the
error came from a `my_error()` call site. See
[`sql/docs/stored-programs.md`](../../sql/docs/stored-programs.md) for
the handler-stack model.

## 9. Format-string safety

`my_error()` / `push_warning_printf()` consume printf-style varargs
([`mysys/my_error.c:105`](../../mysys/my_error.c)). Authoritative rules
in [`logging-and-errors.md`](../review/logging-and-errors.md)
§"Format-string and printf safety":

- **Length-bounded strings:** `%-.<N>s` for `const char*` from
  untrusted / variable-length input. Bare `%s` on a 10MB input
  produces a 10MB log line (PR4455 grooverdan).
- **Non-NUL-terminated bytes:** `%.*s` with `int(len)`. Required for
  InnoDB record bytes, wire payloads, file slices.
- **Identifiers:** `%sQ` (MariaDB extension) does backtick quoting
  *and* charset conversion. Don't write `` `%s` `` by hand.
- **Integer width:** `%llu` for `unsigned long long`, `%zu` for
  `size_t`, `%lld` for `long long`. Don't keep legacy
  `(unsigned long long) val` casts (PR4869).
- **`errno`:** `%iE` (13.0+) or `%M` (10.11). Never hand-enumerate
  `EACCES`/`EMFILE`/`ENOMEM` (PR4874).
- **Stack buffers:** `snprintf(buf, sizeof(buf), …)`. Never `sprintf`,
  never hard-coded sizes that don't match the buffer.

Compiler `-Wformat` and UBSan catch most mismatches at build time.
`MYSQL_MAINTAINER_MODE=ERR` (CI default) treats them as build failures.

## 10. InnoDB identifier display

InnoDB stores table/index names in the **`my_charset_filename`**
encoding (filename-safe — e.g. `@002d` for `-`). A bare `%s` on those
bytes produces garbled output for non-ASCII names and mojibake for
plain ASCII names with reserved characters.

The conversion path is **`ut_get_name()`** (or `dict_table_open_failed()`
for the table-open error path) — converts from `my_charset_filename`
to `system_charset_info` (UTF-8). PR4342 dr-m:
"a more efficient way of displaying InnoDB table names. A conversion
from `my_charset_filename` to `system_charset_info` (UTF-8). A test
case for this must …".

Rule: any new InnoDB log/error message that prints a table or
constraint name **must** convert first, and a test case with non-ASCII
identifiers must verify the output. See
[`logging-and-errors.md`](../review/logging-and-errors.md) §"InnoDB
identifier display".

## 11. Pitfalls

- **`my_error()` followed by `return 0`.** Error on DA, caller reports
  success, error lost. Defence: `DBUG_ASSERT(thd->is_error())` at
  error-return sites.
- **Mixing `printf` / `fprintf(stderr, …)` / `puts` with `sql_print_*`.**
  Forbidden in server code (PR4262). Use `fwrite()` for `FILE*` byte
  output, not `fprintf("%s", …)` (PR4605).
- **Numeric error code in MTR `--error 1234`** instead of `--error
  ER_NAME`. Reviewers reject; names are stable, numbers visually
  unhelpful. See [`mysql-test/CLAUDE.md`](../../mysql-test/CLAUDE.md)
  §"mysqltest directive cheat-sheet".
- **Reordering or inserting in `errmsg-utf8.txt`.** Numeric codes are
  an ABI — old code = old number forever. Append at the end.
- **Logging per-row in a hot path.** A `sql_print_warning()` in a
  replication-applier loop produces gigabytes under legitimate
  operation. PR4342 janlindstrom on `DB_LOCK_WAIT`: "it would flood
  error log if this warning is enabled in release builds." See
  [`logging-and-errors.md`](../review/logging-and-errors.md)
  §"Cold-path warnings — don't flood".
- **`push_warning_printf` with `WARN_LEVEL_ERROR`.** The levels are a
  severity *classification* shown in `SHOW WARNINGS`; setting
  `level=ERROR` does **not** abort the statement. To abort, use
  `my_error()`.
- **`thd->is_error()` cleared by an inner statement during SP
  execution.** Stored-routine sub-statements maintain their own DA;
  when a trigger / SQL function returns successfully the outer DA may
  have been reset. Check `is_error()` *before* nested-statement
  boundaries, or save the error code locally.
- **Forgetting `ER_THD(thd, ER_FOO)` as the 2nd arg to
  `push_warning_printf`.** That argument is the locale-translated
  format string. A hand-written literal breaks i18n.
  ```c
  push_warning_printf(thd, Sql_condition::WARN_LEVEL_WARN,
                      ER_FOO, ER_THD(thd, ER_FOO), arg1, arg2);
  ```
- **Editing `include/mysqld_error.h` directly.** Regenerated by
  `comp_err` from `errmsg-utf8.txt` every build. Edits vanish.

## 12. Recipes (grep)

```sh
# Every my_error call site for a given code
grep -rn 'my_error(\s*ER_FOO_BAR' sql/ storage/ plugin/

# Unbounded %s in error messages (length-injection risk)
grep -nE '"[^"]*%s[^"]*"' sql/share/errmsg-utf8.txt \
  | grep -v '%-\.[0-9]\+s' | grep -v '%\.\*s'

# push_warning_printf callers missing ER_THD
grep -rnE 'push_warning_printf\([^)]*\)' sql/ | grep -v ER_THD

# Last 20 entries appended to errmsg-utf8.txt
grep -nE '^(ER_|WARN_)[A-Z_]+\s*$' sql/share/errmsg-utf8.txt | tail -20
```
