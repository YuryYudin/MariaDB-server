# Playbook: Add a new error / warning message

**Use when:** you need a **new** user-visible diagnostic — a new `ER_*` code raised via `my_error()` or `push_warning_printf()` — because no existing code in [`sql/share/errmsg-utf8.txt`](../../sql/share/errmsg-utf8.txt) covers the situation.
**Skip if:** (a) the message goes only to the server error log (use `sql_print_error()` / `sql_print_warning()` / `sql_print_information()` directly — **no `errmsg-utf8.txt` entry needed**); (b) you're rewording an existing message (just edit the entry in place — see MDEV-39546 `96b3dd0c344`); (c) a generic code like `ER_STD_INVALID_ARGUMENT`, `ER_WRONG_ARGUMENTS`, `ER_BAD_OPTION_VALUE` fits ([`logging-and-errors.md`](../review/logging-and-errors.md) §"Error codes / `errmsg-utf8.txt`": "Reuse generic codes … Don't mint hyper-specific ones." — PR4569).
**Typical effort:** 30-60 minutes including the test.

## Overview

A "new error message" in MariaDB has three moving parts:

1. **Definition.** Append a new `ER_*` (or `WARN_*`) entry at the **end** of [`sql/share/errmsg-utf8.txt`](../../sql/share/errmsg-utf8.txt). `comp_err` regenerates the C header (`mysqld_error.h`) at build time — you never hand-edit the header.
2. **Call site.** Decide error vs. warning vs. error-log per the decision table in [`sql/CLAUDE.md`](../../sql/CLAUDE.md) §"`my_error()` vs `push_warning_printf()` vs `sql_print_error()`"; call the right function with matching format-string args.
3. **Test.** Drive the call site from SQL; assert via `--error ER_FOO_BAR` (errors) or check `SHOW WARNINGS` content (warnings). See [`add-mtr-test.md`](add-mtr-test.md).

The rules around wording, format specifiers, identifier quoting, and message style are the authoritative concern of [`.claude/review/logging-and-errors.md`](../review/logging-and-errors.md) — don't restate them; read.

## Files you'll touch

| File | Role |
|---|---|
| [`sql/share/errmsg-utf8.txt`](../../sql/share/errmsg-utf8.txt) | Append the new `ER_*` / `WARN_*` entry at the **end of the file** (stable numeric ABI — never reorder or insert). |
| `sql/<file>.cc` (or `storage/*/`, `plugin/*/`) | Call `my_error()` / `push_warning_printf()` at the relevant site. |
| `mysql-test/<suite>/t/<test>.test` | Exercise the new path; use `--error ER_FOO_BAR` (errors) or `SHOW WARNINGS` (warnings). |
| `mysql-test/<suite>/r/<test>.result` | Recorded result — captured by `./mtr --record`, **never hand-edited**. |

You do **not** edit `include/mysqld_error.h` — it is auto-generated by `comp_err` from `errmsg-utf8.txt` at build time. Editing it has no effect (next build overwrites it).

## Steps

1. **Reuse-first check.** Generic codes are preferred — minting hyper-specific ones invites reviewer pushback (PR4569). Search:

   ```sh
   grep -iE '<keyword1>|<keyword2>' sql/share/errmsg-utf8.txt | head -20
   ```

   Common reusable codes: `ER_WRONG_ARGUMENTS`, `ER_STD_INVALID_ARGUMENT`, `ER_BAD_OPTION_VALUE`, `ER_NOT_SUPPORTED_YET`, `ER_FEATURE_DISABLED`, `ER_ILLEGAL_PARAMETER_DATA_TYPES2_FOR_OPERATION`. If one fits — use it. Reword if the message is wrong (that's a no-new-code change; see MDEV-39546 below).

2. **Pick the kind: error vs. warning vs. error-log.** Use the table from [`sql/CLAUDE.md`](../../sql/CLAUDE.md) §"`my_error()` vs `push_warning_printf()` vs `sql_print_error()`":

   | Kind | API | Visible to | Aborts? |
   |---|---|---|---|
   | Error | `my_error(ER_FOO, MYF(0), …)` | Client (`SHOW WARNINGS` + statement error) | Yes — statement aborts |
   | Warning / note | `push_warning_printf(thd, Sql_condition::WARN_LEVEL_WARN, ER_FOO, ER_THD(thd, ER_FOO), …)` | Client (`SHOW WARNINGS`) | No |
   | Error log only | `sql_print_error()` / `sql_print_warning()` / `sql_print_information()` | DBA (error log) | No |

   The error-log path needs **no `errmsg-utf8.txt` entry** — the format string is literal. Stop here if that's your case.

3. **Append the new entry at the end of [`sql/share/errmsg-utf8.txt`](../../sql/share/errmsg-utf8.txt).** Open the file and add at the bottom — never insert in the middle (numeric codes are part of MariaDB's ABI; old code = old number forever). The shape, verified from the last entries in the file:

   ```
   ER_WARN_QB_NAME_PATH_NOT_SUPPORTED_INSIDE_VIEW
           eng "Hint %s is ignored. QB_NAME hints with path are not supported inside view definitions."
   ```

   Two lines: the symbol on its own line, then a TAB- or space-indented `eng "…"` string. Translations (`chi`, `cze`, …; the full list is on the `languages` line at the top of the file) follow over time, filled in by translators — **new entries typically ship with `eng` only**. Confirmed by inspecting the last ~50 entries in the file (e.g. `MDEV-39304`, `MDEV-39500`, `MDEV-10152` all landed `eng`-only).

4. **Choose the format specifiers carefully.** The string is consumed by `my_error()`'s printf-style varargs (`include/my_sys.h`). Common specifiers used across `errmsg-utf8.txt`:

   | Specifier | For | Example use |
   |---|---|---|
   | `%s` | `const char *` (NUL-terminated) | `"Table not found '%s'"` |
   | `%-.<N>s` | length-bounded string | `"Can't create file '%-.200s'"` — see [`logging-and-errors.md`](../review/logging-and-errors.md) §"Format-string and printf safety" |
   | `%.*s` + `int(len)` | non-NUL-terminated bytes | for InnoDB record bytes etc. |
   | `%sQ` | SQL identifier with backtick quoting | `"Can't create table %sQ.%sQ"` (custom MariaDB extension) |
   | `%d`, `%u`, `%lld`, `%llu`, `%zu` | integers (match the type) | `"%llu rows affected"` |
   | `%iE` (13.0+) / `%M` (10.11) | `errno` rendered as `EACCES`/`ENOMEM`/… | never hand-enumerate; PR4874 |

   Match the call-site arguments exactly. A format-string mismatch is a buildbot break on `-Wformat`-strict configurations and on UBSan ([`logging-and-errors.md`](../review/logging-and-errors.md) §"Format-string and printf safety").

5. **Identifier quoting.** SQL object names get backtick quoting. Prefer `%sQ` for identifiers (it does the quoting and charset conversion); use `'%s'` (literal single quotes) for free-form strings, never `%s` bare in user-visible text ([`logging-and-errors.md`](../review/logging-and-errors.md) §"Identifier quoting"). For InnoDB identifiers specifically, the raw bytes are in `my_charset_filename` and need conversion via `ut_get_name()` — see [`logging-and-errors.md`](../review/logging-and-errors.md) §"InnoDB identifier display" (PR4342).

6. **Wording.** Read [`logging-and-errors.md`](../review/logging-and-errors.md) §"Message wording" before pushing. The headline rules:
   - Tell the user what happened **and** what to do about it (PR4874, PR4789).
   - Include the object name (table / constraint / variable) the error is about (PR4342, PR4884).
   - Bound user-supplied components with `%-.<N>s` so a 10MB input doesn't produce a 10MB log line (PR4455).
   - No absolute paths, no emojis, no jokes (PR4342).
   - No `err: err:` duplication — only one path adds the prefix (PR4342).

7. **Add the call site.** Examples (real, in-tree):

   - Error that aborts the statement:
     ```cpp
     my_error(ER_FOO_BAR, MYF(0), table_name, col_name);
     return 1;
     ```
   - Warning that lets execution continue (the MDEV-39304 pattern from `sql/opt_hints_parser.cc`, commit `a2f9ad87cfd`):
     ```cpp
     push_warning_printf(
         thd, Sql_condition::WARN_LEVEL_WARN,
         ER_WARN_QB_NAME_PATH_NOT_SUPPORTED_INSIDE_VIEW,
         ER_THD(thd, ER_WARN_QB_NAME_PATH_NOT_SUPPORTED_INSIDE_VIEW),
         str.c_ptr_safe());
     ```
     Note the `ER_THD(thd, ER_*)` second argument — this is the translated format string for the connection's language. Don't pass a literal `"%s …"` there.
   - Error log only (no `ER_*` needed):
     ```cpp
     sql_print_error("Cannot bind to socket %s: %iE", path, errno);
     ```

8. **Write the test.** See [`add-mtr-test.md`](add-mtr-test.md) for the full playbook. Two shapes here:

   - Error path:
     ```
     --error ER_FOO_BAR
     SELECT bad_thing();
     ```
     Always use the **`ER_*` name**, never the numeric code — names are stable, numbers ABI-fixed but visually unhelpful and reviewers reject `--error 1234` outright ([`mysql-test/CLAUDE.md`](../../mysql-test/CLAUDE.md) §"mysqltest directive cheat-sheet").
   - Warning path: warnings don't fire `--error`; the statement succeeds. Assert via `SHOW WARNINGS`:
     ```
     SELECT thing();          # produces warning
     SHOW WARNINGS;           # diff'd against .result
     ```

   For error-log messages (no `ER_*`), use [`include/search_pattern_in_file.inc`](../../mysql-test/include/search_pattern_in_file.inc) against the server's error log ([`logging-and-errors.md`](../review/logging-and-errors.md) §"Testing every message you add").

9. **Record and run.** From the build directory:
   ```sh
   cd <build>/mysql-test
   ./mtr --record main.<test>     # produces .result
   ./mtr main.<test>              # confirms it now passes
   ```
   Inspect the `.result` diff (`git diff`) — the new line(s) should show the message **exactly** as the user will see it. Read it once aloud: that's what users will Google when they hit this.

10. **Build once.** Confirm `comp_err` regenerates `mysqld_error.h` cleanly (no parse error in `errmsg-utf8.txt`) and the call site compiles against the new symbol. A typo in the `ER_*` symbol or a mismatched `%` count surfaces at build time, not at test time.

11. **Commit.** Test + code + `errmsg-utf8.txt` go in **one commit** (per [`add-mtr-test.md`](add-mtr-test.md) — keeps `git bisect` honest). Subject line: `MDEV-NNNNN <short description>`.

## Pitfalls and rejection patterns

- **Inserting in the middle of `errmsg-utf8.txt`.** Codes are an ABI; older codes keep their numbers forever. New entries go at the END. [`logging-and-errors.md`](../review/logging-and-errors.md) §"Error codes / `errmsg-utf8.txt`".
- **Format-string / arg mismatch.** Compiler `-Wformat` and UBSan catch most cases, but `%llu` on a 32-bit value, or `%s` on a `String` rather than `c_ptr_safe()`, sneaks through. PR4869 (×2) — "use %llu and remove the casts" — [`logging-and-errors.md`](../review/logging-and-errors.md) §"Format-string and printf safety".
- **Identifier-quoting mix.** Don't write `"… table %s for column \`%s\`"` — pick one style; prefer `%sQ` for identifiers. [`logging-and-errors.md`](../review/logging-and-errors.md) §"Identifier quoting".
- **Numeric error code in tests.** `--error 1234` is rejected — names are stable. Use `--error ER_FOO_BAR`. [`mysql-test/CLAUDE.md`](../../mysql-test/CLAUDE.md) §"mysqltest directive cheat-sheet" (PR4569, PR4712).
- **Mistaking a warning for an error.** `push_warning_printf()` does **not** abort. If the test does `--error ER_FOO` and the call site uses `push_warning_printf`, the statement *succeeds* and the test fails with "got 0, expected ER_FOO". See [`sql/CLAUDE.md`](../../sql/CLAUDE.md) §"`my_error()` vs `push_warning_printf()` vs `sql_print_error()`".
- **Forgetting `ER_THD(thd, ER_FOO)` in `push_warning_printf`.** The second arg is the translated format string for the connection's locale; passing a hand-written literal breaks i18n.
- **Cold-path warning floods.** Don't add a warning that fires per-row in normal applier operation — production error logs balloon. [`logging-and-errors.md`](../review/logging-and-errors.md) §"Cold-path warnings — don't flood" (PR4342).
- **Wording style problems.** All-caps, verbose, jargon-laden, no actionable component, no object name. Read [`logging-and-errors.md`](../review/logging-and-errors.md) §"Message wording" before pushing — these get rewritten constantly (PR4342, PR4874, PR4884, PR4789).
- **Adding a code without a call site (dead code).** `grep -r ER_FOO sql/ storage/ plugin/` — there must be a caller. Reviewers spot the dead entry.
- **No test for the message wording.** A `.result` file that captures the exact text is the only protection against silent regressions. [`logging-and-errors.md`](../review/logging-and-errors.md) §"Testing every message you add" (PR4342).
- **Editing `include/mysqld_error.h` instead of `errmsg-utf8.txt`.** The header is regenerated by `comp_err` on every build — your edit will vanish.
- **Using `printf` / `fprintf(stderr, …)` / `puts()` / `ib::logger`** in new code. Forbidden — see [`logging-and-errors.md`](../review/logging-and-errors.md) §"Logging functions" (PR4036, PR4262).

## Validation

The deliverable check:

```sh
cd <build>
cmake --build . -j$(nproc)           # confirms comp_err regenerates cleanly
cd mysql-test
./mtr <suite>.<test>                  # the new test passes
git diff -- mysql-test/<suite>/r/     # the .result diff shows the new message text exactly
```

Then run a related suite (`./mtr --suite=<suite>`) to catch any other `.result` file that mentioned the wording you changed (relevant when **rewording**; less so for a fresh `ER_*`). The numeric error code is deterministic across builds (`comp_err` produces the same value from the same `errmsg-utf8.txt`).
